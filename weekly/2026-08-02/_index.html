Root cause

tgl_truth.py is working correctly and runs every hour. The most recent run generated all five missing days (07-29=21, 07-30=24, 07-31=25, 08-01=9, 08-02=8 TGLs). The data is not lost — it is being discarded before it is committed.

In .github/workflows/daily.yml, step "TGL ground truth (trailing 8 days)", the inline ytd_sources.json heredoc crashes:

File "<stdin>", line 17, in <module>
AttributeError: 'list' object has no attribute 'get'

cache/tgls_created.json holds a list of lists, not a list of dicts. The step runs under bash -e, so this non-zero exit aborts the step before its git add tgl_truth/ / commit / push ever run. A later step's git status in the same run confirms it — tgl_truth/2026-07-29.json … 2026-08-02.json sit there untracked. The step is continue-on-error: true, so the workflow reports success and nothing surfaces.

Fix — one line. The heredoc is the only unguarded command in that step; the two lines above it already use the guard idiom. Append the same guard: 
python - <<'PYEOF' || echo "ytd_sources failed"
  ...
PYEOF
Because tgl_truth.py rewrites the trailing 35 days on every run, the first run after this fix backfills all five missing days automatically. No recovery work is needed. Re-run the weekly rollup afterwards for correct numbers.
