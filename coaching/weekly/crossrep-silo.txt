## CONTEXT
You will receive banded SILO Field Strategy Guide coaching reports for any number of {{COMPANY}}
HVAC SILO technicians. Each was produced using the identical V7.5 SILO banded format and process. You
do NOT have raw transcripts here — work ONLY from the data in the uploaded reports.

The 5 SILO steps assessed in every report are, in this exact canonical order:
1. Ready
2. Welcome
3. Assessment
4. Decision
5. Deliver

Each step is assigned ONE band from the five-band Strength Band Key (below) and backed by a direct
quote — never a number. SILO outcomes are: Repair Won (Option A/B approved), Option C Handoff (customer
chose to explore an upgrade and the tech initiated the Comfort Advisor handoff), and No-Move (all
options declined). A SILO tech is NEVER scored on closing a system upgrade — that is the Comfort
Advisor's job, not the tech's. Both outcome rates, the defining strength and its band, the single
biggest gap and its band, the positive-outcome-vs-no-move contrast per step, strengths, gaps, coaching
priorities, and Beyond-the-Guide patterns are documented in each tech's report.

THE STRENGTH BAND KEY (the currency of this comparison — the same five bands used in every per-tech
report):
* Strong — executed well and consistently across the tech's calls.
* Strong on wins — clearly present on positive-outcome calls (repair won or Option C handoff), drops
  off or disappears on no-moves. This is the coaching band: a behavior the tech can already do but
  doesn't do every time.
* Solid — reliably present, gets the job done, but not a standout.
* Moderate — inconsistent; present on some calls, absent on others, no clear positive/no-move pattern.
* Weak — rarely attempted, or attempted poorly, across the tech's calls.
A step may also carry "—" (genuinely not applicable / no instance found), explained in that tech's
Appendix. For the Option C handoff specifically, "—" on a call where no upgrade interest arose is NOT a
failure. Treat "—" as not-applicable, not as a band, and exclude it from band tallies for that step
(note the exclusion).

NO-NUMERIC-SCORING RULE (LOCKED — INHERITED FROM THE PER-TECH REPORTS):
* Do NOT assign or reintroduce 1–5 scores, step averages, per-call numbers, score thresholds, or any
  numeric rating anywhere in this comparison.
* The ONLY numbers permitted as performance scores are each tech's Repair-Won rate and Option C Handoff
  rate (counts and %), and team-level rate figures derived from them (team rate, range, median).
* Simple tallies are allowed and expected — e.g., "5 of 8 techs band Decision as 'Strong on wins'" —
  because these count bands, they do not score them.
* Every cross-tech assessment is expressed in bands and justified with a quote carried up from a tech's
  report.

BAND ORDERING (for ranking, tallies, and "highest/lowest" language — use this fixed order only):
Strong (highest) > Solid > Strong on wins > Moderate > Weak (lowest).
Rationale, fixed so every comparison sorts identically: Strong is consistent execution everywhere;
Solid is reliable; Strong on wins is real ability applied inconsistently (above Moderate because the
skill exists); Moderate is inconsistent with no pattern; Weak is rare or poor. Never invent a different
ordering. "Strong on wins" is always treated as the priority coaching band regardless of its rank
position, because it marks the largest recoverable upside.

SCALABILITY RULE: These instructions work with any number of techs — 2 or 20. Every section scales to
the actual number of reports present. Never hardcode a tech count.

## STEP 0 — NORMALIZATION PASS (RUN BEFORE ANYTHING ELSE)
=======================================================================
The per-tech reports come from a fixed prompt that produces small, predictable variations. Reconcile
them the SAME way for every report or team-wide tallies will be inconsistent. Apply all of the following
before extracting a single data point.

NORM-1 — CANONICAL STEP LABELS.
Treat cosmetic label variants as the SAME step and use the canonical names (Ready, Welcome, Assessment,
Decision, Deliver) everywhere. Match on meaning and position in the 5-step set — never create a 6th step
because a label was worded differently.

NORM-2 — THE BAND SOURCE RULE (LOCKED — DO NOT DEVIATE).
For each tech's per-step band, read the band printed in that tech's STRATEGY GUIDE SCORECARD (Section
4), "Band" column, EXACTLY AS PRINTED. Use that band verbatim in every scorecard, leaderboard, and
tally.
* NEVER infer or upgrade/downgrade a band from the prose in Sections 5–7.
* NEVER convert a band to a number, or a number back to a band.
* Section 4 "Band" is the single source of truth for a tech's per-step band. Full stop. The only
  permitted value other than the five bands is "—" (not applicable), handled per the Strength Band Key
  note above.

NORM-3 — THE POSITIVE-OUTCOME/NO-MOVE PATTERN SOURCE RULE.
When you need how a step behaved on positive-outcome calls versus no-moves (for Top Performer Analysis,
Company-Wide Pattern correlation, and the Positive-Outcome Predictor Test), read it from that tech's
Section 7 ("WHAT SEPARATES POSITIVE OUTCOMES FROM NO-MOVES"), which states each step as a
band-on-positive-vs-band-on-no-move contrast or a one-phrase contrast, with quotes. Capture the contrast
and at least one supporting quote — never a number.

NORM-4 — THE SUPPORTING QUOTE IS LOAD-BEARING.
For every band you carry up, also carry the exact supporting quote and call number printed beside it in
the report's Section 4, and any contrasting quote from the report's Section 7. Quotes are how this
comparison shows evidence. If a report's Section 4 row shows "No instance found in transcripts," treat
the band as printed (usually Weak) and carry that phrase as the evidence.

NORM-5 — UNIQUE CALLS, NOT TOTAL FILES.
Each report has a "unique calls analyzed / unique service calls" figure (after duplicates and
non-scoreable/unusable contacts were removed) and a larger "total files provided" figure in Section 3.
ALWAYS use the UNIQUE figure ("[X] unique service calls" from Section 3, equal to the header's "[X]
Unique Calls Analyzed"). Never use total-files-provided as a tech's call count.

NORM-6 — STRONGEST / WEAKEST SELECTION.
Each report's Section 3 names TWO strongest steps and TWO weakest steps, each with its band. The
scorecard has one "Strongest" and one "Weakest" column. For the column value:
* Strongest column = the higher-banded of the two named strongest steps, using BAND ORDERING. If the
  two carry the same band, use the one listed first.
* Weakest column = the lower-banded of the two named weakest steps, using BAND ORDERING. If tied, use
  the one listed first. Do this identically for every tech.

NORM-7 — STRENGTHS COUNT NORMALIZATION.
Section 5 of a per-tech report contains 3 OR 4 strengths in printed order (the report leads with
genuine standouts), each banded and quote-backed. When you need "top 3 strengths," take the FIRST THREE
as printed, in order, with their bands and quotes. If a report has only 3, use all 3. Never reorder by
your own judgment.

NORM-8 — PRIORITIES COUNT.
Section 9 contains exactly 3 ranked coaching priorities plus an italicized fourth-priority note. Use the
3 ranked priorities. The fourth note is context only.

NORM-9 — LOAD-BEARING HEADINGS.
You locate each data point by the per-tech report's section headings and the exact phrase "Beyond the
Guide." These strings are how extraction works. If a heading is intact, read normally. If a heading is
renamed, missing, or merged, do NOT guess content from surrounding text — treat that data point as
unreadable for that tech and apply the Data Integrity Protocol.

NORM-10 — TWO RATES PER TECH.
SILO reports carry TWO outcome rates: a Repair-Won rate (A/B approved) and an Option C Handoff rate.
Extract BOTH from Section 1 / Section 3.

MANAGER'S DOCTRINE (LOCKED 2026-07-18): SILO techs are not sellers — their job is to FLIP the
call: surface the upgrade conversation and create the turnover lead that gets a Comfort Advisor
into the home to sell the equipment. The Option C Handoff is the PRIMARY win and the lens for the
whole comparison. Rank the master scorecard by Option C Handoff rate (primary), with Repair-Won
rate shown as its own column and used as the tiebreaker (band-quality tally breaks remaining
ties). Frame the team analysis, the separating behavior, and the one-intervention recommendation
around what produces handoffs. A won repair is a positive secondary outcome, never the headline.
Never collapse the two rates into one number, and never frame a low Repair-Won rate as failure —
the failure pattern worth naming is upgrade-candidate calls that ended with no handoff.
These two rates are the only numbers permitted anywhere in the comparison.

## STEP 0.5 — DATA INTEGRITY PROTOCOL (QUARANTINE, NEVER SKIP)
=======================================================================
A malformed or inconsistent report must never silently drop out and must never be tallied around
invisibly.

DI-1 — KEEP THE TECH IN THE ROSTER. Every uploaded tech appears in the Appendix roster and, wherever
data permits, in the scorecard and snapshots. Never delete a tech for being malformed.

DI-2 — EXCLUDE ONLY THE AFFECTED CALCULATION. If a specific data point is missing/unreadable (e.g., one
step Band is blank, or Section 7 is absent), exclude that tech from ONLY the team tallies needing that
specific point. Keep them in every other tally. (A missing Section 7 removes a tech from the
positive/no-move contrast and the Positive-Outcome Predictor Test only — they remain in the scorecard,
step leaderboard for steps that do have a band, and roster.)

DI-3 — SHOW THE HOLE, DON'T FILL IT. In any cell where a value is unavailable, print "N/A — see Data
Integrity", never a blank, a guessed band, or an estimate. Never substitute a typical band or a guessed
value for a missing tech value.

DI-4 — RECORD EVERY ISSUE. Maintain a running Data Integrity list: tech name, exactly what was
missing/ambiguous/inconsistent, which canonicalization (if any) you applied, and which tallies the tech
was excluded from. Prints in the Appendix.

DI-5 — TEAM TALLIES ARE COMPUTED ON AVAILABLE DATA ONLY. When a tech is excluded from a specific tally,
the team figure for that tally is computed over the techs that DO have the data, and you must state the
denominator (e.g., "Welcome bands as Strong for 5 of 8 techs; Tech X excluded — see Data Integrity").
Never let a missing value distort a count, and never quietly change the denominator without saying so.

DI-6 — MINIMUM VIABLE REPORT. If a report is so malformed that neither a single step Band (Section 4)
nor an outcome rate (Section 1/3) can be read, that tech appears in the roster and Data Integrity list
as "insufficient data to assess," is excluded from all band-based and rate tallies, and is still counted
in the total uploaded-reports count. Say so explicitly. Do not drop them.
